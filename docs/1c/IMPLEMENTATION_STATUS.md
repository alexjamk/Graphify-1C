# Состояние Graphify-1C

## Реализовано

- Чтение файловой выгрузки Конфигуратора и проекта EDT, включая пути с кириллицей.
- Единый запуск для структуры `src/cf` и всех корректных непосредственных дочерних каталогов `src/cfe`.
- Узлы метаданных, реквизитов, табличных частей, модулей, процедур, функций и форм со стабильными ID и исходными путями.
- Связи типов, локальные вызовы, вызовы общих и глобальных модулей, переходы клиент → сервер.
- Подписки на события, регламентные задания, подсистемы, маршруты HTTP-сервисов и основные права ролей.
- Запросы из литералов и последовательной сборки строк внутри процедуры; чтение таблиц, соединений и виртуальных таблиц.
- Отдельные узлы расширений с `source_type` и `extension_name`, связи `EXTENDS`, `BEFORE`, `AFTER`, `INSTEAD`, `CHANGE_CONTROL`.
- JSON сохраняет `metadata_type`, `source_path` и `relation_type` вместе с исходными атрибутами Graphify.
- Индексированный поиск вызовов между базой и расширениями с сохранением неоднозначности.
- Записи движений через `Добавить()` и `Записывать = Истина`, в том числе из расширения в регистр базы.
- Выгрузка в JSON и интерактивный HTML через существующий экспорт Graphify с дополнительными 1С-фильтрами; команды `explain`, `path` и `query` читают сохранённый граф.
- Поиск в viewer по имени, полному ID и расширению; фильтры источников, типов узлов и связей. Для большого графа связи выбранного узла разделены по типу и направлению с загрузкой по 20; обход на 2–3 уровня ограничен числом узлов и связей.
- Для графов свыше 5000 узлов локальный HTML не рисует весь граф при открытии; рядом создаётся агрегированный обзор сообществ.
- Сводная диагностика CLI: количество объектов и методов, разрешённые и неизвестные вызовы, чтения запросов и ссылки на метаданные.
- Дисковый SQLite-индекс большого 1С-графа для повторных запросов без загрузки всего JSON в память; мультиграф сохраняет разные отношения между одной парой узлов.
- `graphify-1c update .` распознаёт выгрузку 1С и полностью перестраивает её граф. Манифест последнего анализа сохраняет выбранные расширения, путь JSON и HTML; для стандартной структуры команда работает и без манифеста. Универсальный `update` для других проектов сохранён.
- Для графов больше 5000 узлов JSON записывается потоком без дополнительных полных копий в NetworkX. Повторяющиеся ID узлов и одинаковые отношения объединяются по правилам исходного мультиграфа. SQLite строится в отдельном файле и заменяет прежний индекс только после успешного завершения. Обновление сначала строит временные JSON/HTML/SQLite и публикует их после успешной сборки.
- Поиск по подстроке в новом индексе использует SQLite FTS5 с триграммами, когда эта возможность доступна; короткий запрос и старые индексы используют прежний поиск. `index explain` и `index path` дают ограниченный контекст и направленный путь без чтения полного JSON в память.

## Известные ограничения

- Ветви, циклы, вызовы вспомогательных методов и межпроцедурный поток данных при восстановлении текста запроса не вычисляются. Неизвестные фрагменты помечаются как частичные.
- Динамические вызовы представлены как неоднозначные факты без придуманной точной цели.
- Простое присваивание результата `СоздатьМенеджерЗаписи()` или `СоздатьНаборЗаписей()` локальной переменной и последующий `Записать()` разрешаются как `writes` с уверенностью `INFERRED`. Передача переменной через параметры, ветви и межпроцедурный анализ пока не покрыты.
- Формы EDT покрывают основные элементы, команды, реквизиты и события; специализированные элементы ещё не моделируются.
- Условия прав ролей и полная семантика web-сервисов не анализируются.
- Двоичные EPF/ERF сначала нужно выгрузить в исходники.
- `update` для 1С пока выполняет полный повторный анализ, а не инкрементальную обработку изменённых файлов. Полная выгрузка крупной ERP-конфигурации (11,1 ГБ) требует дополнительной оптимизации памяти: пробный запуск остановлен при росте потребления до 3,5 ГБ и малом объёме свободной памяти.
- Порядок регистрации нескольких расширений хранится в информационной базе и не восстанавливается из одной файловой выгрузки. Без этих данных граф показывает все перехваты, но не утверждает порядок исполнения итоговой конфигурации.
- Для большого графа просмотр требует запуска локального сервера; открытие HTML напрямую как `file://` не даёт доступа к поиску и окружению из SQLite. Для глубины 2–3 предел ответа API — 300 узлов и 800 связей; на глубине 1 группа загружается по 20 связей. Производительность на конфигурациях масштаба крупной ERP ещё не измерена.
- Счётчик неразрешённых вызовов включает стандартные методы платформы без BSL-цели; это диагностика, а не число ошибок.

## Проверки

- После потоковой записи и безопасного обновления повторный запуск `update` на конфигурации «Управление торговлей» 11.5.27.52 с двумя выбранными расширениями завершился: 552 278 узлов и 1 223 778 связей. Обновлены JSON, HTML и SQLite; поиск по SQLite проверен на реальных данных. 115 смежных тестов и Ruff прошли (18 сентября 2026 года).
- После постраничной навигации прошёл 111 смежных тестов; Ruff и синтаксическая проверка JavaScript прошли (18 сентября 2026 года).
- 123 смежных теста прошли, включая генерацию HTML для малого и большого графа; Ruff прошёл (18 сентября 2026 года).
- В Edge вручную проверены открытие HTML, поиск и локальный граф выбранной процедуры.
- Открытая небольшая выгрузка Конфигуратора: 438 узлов, 686 связей.
- Синтетическая конфигурация из 5000 документов: 20 001 узел и 25 000 связей за 16,66 с, пик памяти 53,4 МБ. Это не заменяет проверку на ERP.
- Для синтетического графа из 6001 узла и 7500 связей локальный HTML создан за 0,34 с; файл занимает 3,54 МБ, агрегированный обзор создан отдельно. В браузере проверен переход к локальному графу через поиск.
- Полный анализ `./src/cf` с двумя явно выбранными расширениями `Расширение 1` и `Расширение 2` завершён: 549 075 узлов, 1 171 531 связь, 191 `EXTENDS`, 16 связей перехватов. Остальные расширения исключены. JSON занимает 2,5 ГБ; при обработке наблюдалось около 2,8 ГБ памяти. По результатам прогона исправлен разбор методов внутри `#Область` и извлечение аннотаций без текста всего модуля.
- После проверки полноты и исправления потери параллельных связей, перехвата модуля приложения и типов метаданных граф конфигурации «Управление торговлей» 11.5.27.52 пересобран: 552 278 узлов, 203 `EXTENDS`, 18 перехватов. Подробные три сценария сравнения с `rg` — в [EVALUATION_UT_11_5_27_52.md](EVALUATION_UT_11_5_27_52.md). Общая полезность графа на разных задачах ещё не доказана.

Проверены 10 конкретных вопросов: 9 ответов графа совпали с исходниками, один остался неполным из-за записи через переменную менеджера записи. Подробности — в [EVALUATION_DOCUMENTS_UT_11_5_27_52.md](EVALUATION_DOCUMENTS_UT_11_5_27_52.md).

## Запуск

```powershell
python -m pip install -e ".[onec]"
graphify-1c analyze ./src --out graphify-out/graph.json --html graphify-out/graph.html
graphify-1c onec path/to/export --out graphify-out/graph.json
graphify-1c explain "ОбработкаПроведения" --graph graphify-out/graph.json
python scripts/benchmark_onec.py --synthetic 100
# Для большого графа с --html: открыть адрес, напечатанный этой командой.
graphify-1c serve graphify-out/graph.html
```
