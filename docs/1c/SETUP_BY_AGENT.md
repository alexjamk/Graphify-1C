# Настройка Graphify-1C агентом по ссылке

Эту страницу можно дать Codex, Claude Code, ChatGPT Desktop Work или агенту VS Code, **если ему доступны локальная папка проекта, терминал и GitHub**. Обычный веб-чат без доступа к компьютеру не сможет установить программу или прочитать локальные исходники. Откройте в агенте **корень своего проекта 1С** и отправьте запрос:

> Прочитай https://github.com/alexjamk/Graphify-1C/blob/main/docs/1c/SETUP_BY_AGENT.md и выполни раздел «Порядок настройки» для открытого проекта. Graphify-1C установи один раз для пользователя; исходники инструмента в мой проект не копируй. Если в `graphify-out/.graphify_onec.json` уже записан выбор расширений, сохрани его. Если выбора ещё нет, включи все корректные непосредственные расширения `src/cfe/*`. Если я указал конкретные расширения отдельно, включи только их. Не загружай весь граф в контекст. В конце покажи проверочные команды и результат поиска одного объекта.

Если агент не может открыть страницу по ссылке, скопируйте ему раздел ниже. Не передавайте в чат выгрузку конфигурации, базы данных или многогигабайтный JSON-граф.

## Порядок настройки

1. Убедись, что текущая рабочая папка — корень проекта с корректной выгрузкой `src/cf`. Прочитай только имена каталогов `src`, наличие `src/cf/Configuration.xml` или `src/cf/Configuration/Configuration.mdo`, существующий `graphify-out/.graphify_onec.json` и действующие `AGENTS.md`/`CLAUDE.md`/инструкции Copilot. Не считывай всю конфигурацию для этой проверки. Если структура нестандартная, опиши её и подбери `analyze` с действительными путями; `init-project` требует стандартный `src/cf`.
2. Проверь `graphify-1c --help`. Если команды нет, проверь Python 3.10+, Git и `python -m pipx --version` (на системах с командой `python3` используй её). При отсутствии pipx установи его через `python -m pip install --user pipx`, выполни `python -m pipx ensurepath`, затем установи один раз: `python -m pipx install --suffix=-1c 'graphifyy[onec] @ git+https://github.com/alexjamk/Graphify-1C.git'`. На Windows при ошибке Git из-за длинных путей включи `git config --global core.longpaths true` и повтори. Если `pipx` уже содержит `graphifyy-1c`, но команда недоступна в текущем терминале, найди каталог приложений через `python -m pipx list` и используй полный путь или открой новый терминал. Не устанавливай форк в окружение оригинального `graphify`.
3. Если есть манифест, считай **только его** и сначала проверь путь к SQLite: замени расширение указанного `html` на `.sqlite`. Поле `extensions` хранит явно переданные `--extension`: пустой список при `root=src` означает автоматическое обнаружение всех корректных `src/cfe/*`, а не отсутствие расширений. Не меняй этот режим или явный выбор самовольно. Для стандартного проекта выполни повторно `graphify-1c init-project . --agents codex,claude,vscode`: команда обновляет только свой ограниченный блок правил и не создаёт дубликатов. Если индекс существует и исходники не менялись, не перестраивай его. Если отсутствует, выполни `graphify-1c update .` из корня проекта.
4. Если манифеста нет и структура стандартная, выполни `graphify-1c init-project . --agents codex,claude,vscode`. Команда сохраняет существующие правила и добавляет `graphify-out/` в `.gitignore`. Затем выбери **один** способ анализа:
   - Все корректные расширения: `graphify-1c analyze ./src --out graphify-out/graph.json --html graphify-out/graph.html`.
   - Только явно выбранные пользователем расширения: `graphify-1c analyze ./src/cf --extension '<путь-к-расширению-1>' --extension '<путь-к-расширению-2>' --out graphify-out/graph.json --html graphify-out/graph.html`. Используй реальные пути и повтори флаг столько раз, сколько нужно. Корень `./src/cf` здесь принципиален: `./src` автоматически обнаруживает **все** расширения.
5. Убедись, что есть `graphify-out/.graphify_onec.json` и ожидаемые JSON/HTML. Для графа более 5000 узлов SQLite создаётся рядом с HTML автоматически. Если его нет, выполни `graphify-1c index build graphify-out/graph.json graphify-out/graph.sqlite`. При нестандартных путях используй значения манифеста.
6. Проверь работу короткими запросами: `graphify-1c index search '<индекс>' 'ЗаказКлиента'` (или имя существующего объекта) и `graphify-1c index groups '<индекс>' '<точный ID>' --direction in`. Сообщи число узлов и связей, число расширений, путь индекса и выбранные расширения **только в локальном ответе пользователю**. Не публикуй личные пути и названия расширений в репозитории инструмента.
7. Для дальнейшей работы прочитай [рабочий порядок агента](AGENT_WORKFLOW.md). Используй `index search/groups/neighbors/explain/path`, страницы связей по 10 и выбор нужного `--relation`; проверяй важные выводы по XML/BSL. Не открывай `graph.json` целиком. После правок исходников запускай `graphify-1c update .`. Для тысяч связей применяй `index export`, не печатай весь JSONL в контекст.

Установка выполняется один раз на компьютере. При переходе ко второму проекту повторяются только шаги проверки структуры, `init-project`, построения или чтения **его** индекса. Графы разных проектов не смешиваются.

## Проверка вручную

Подробные команды для Windows и пояснения для macOS/Linux находятся в [пошаговой инструкции](QUICKSTART_AGENTS.md). Примеры постоянных правил: [Codex](examples/AGENTS.md), [Claude Code](examples/CLAUDE.md), [VS Code](examples/copilot-instructions.md). Эти правила обычно создаёт `init-project`; не нужно копировать их поверх существующих файлов вручную.
