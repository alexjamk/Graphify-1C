# Пилотная оценка: граф и поиск по исходникам

Дата: 18 сентября 2026 года. Корпус: `./src/cf` и только расширения `Расширение 1`, `Расширение 2`.

## Что сравнивалось

Использован один и тот же снимок исходников. Граф: 552 278 узлов, 1 222 312 связей; экспорт JSON — 2623 МБ. Построчно построенный SQLite-индекс: 1224 МБ, 47,76 с на подготовку. Каждый запрос выполнен пять раз; ниже медиана времени одного повторного запроса. Время полного анализа конфигурации в эти цифры не включено.

| Задача | Граф, результат и время | `rg`, результат и время | Проверка смысла |
| --- | --- | --- | --- |
| Найти связи с `ОбменДаннымиСервер.ВыполнитьОбменДаннымиПоРегламентномуЗаданию` | 2 связи, 0,0003 с | 4 строки, 1,9535 с | Граф дал вызов и `INSTEAD`; в строках `rg` дополнительно были два определения. |
| Перечислить перехваты двух расширений | 18 связей с базовыми методами, 0,0002 с | 18 директив, 0,0418 с | Все 18 директив разрешены; ранее два случая выявили и помогли исправить ошибки графа. |
| Найти заимствованные объекты | 203 `EXTENDS`, 0,0004 с | 204 XML, 0,0551 с | 203 XML имеют пару в базе. Для `ОтчетОСписанииТоваровУХранителя` объекта в `src/cf` нет, поэтому `EXTENDS` отсутствует обоснованно. |

В этих трёх сценариях **повторные структурные запросы** к подготовленному индексу быстрее и дают готовые типизированные отношения. `rg` остаётся прямым способом найти текст и проверить найденное по исходнику. Если нужен всего один простой поиск, следует учитывать затраты на анализ графа и индекс; этот пилот не доказывает общего выигрыша для всех задач.

## Воспроизведение

```powershell
graphify-1c analyze './src/cf' `
  --extension './src/cfe\Расширение 1' `
  --extension './src/cfe\Расширение 2' `
  --out graphify-out\ut-11-5-27-52.json
graphify-1c index build graphify-out\ut-11-5-27-52.json graphify-out\ut-11-5-27-52.sqlite
python scripts\evaluate_onec.py --database graphify-out\ut-11-5-27-52.sqlite `
  --base './src/cf' `
  --extension './src/cfe\Расширение 1' `
  --extension './src/cfe\Расширение 2' `
  --method 'ВыполнитьОбменДаннымиПоРегламентномуЗаданию' `
  --target-id '1c://CommonModule/ОбменДаннымиСервер/CommonModule/ВыполнитьОбменДаннымиПоРегламентномуЗаданию'
```

## Что ещё нужно для оценки полезности

Это три выбранных сценария, а не случайная или слепая выборка. Следующая проверка должна включить 20–30 задач из реальной разработки: поиск вызывающих методов, влияние изменения реквизита, движение данных от формы до регистра, пересечения расширений, а также простые текстовые поиски, где граф может проигрывать. Для каждой задачи нужен независимо подтверждённый ответ и одинаковый лимит времени у исполнителей. Измерять следует полноту, ложные связи, время до проверенного ответа и число просмотренных файлов. Только после такого испытания можно делать общий вывод о пользе графа.
