# Graphify-1C в ChatGPT, Codex, Claude Code и VS Code

Эта инструкция рассчитана на проект 1С с файловой выгрузкой. Команды выполняются **из корня проекта 1С**, где находится каталог `src`. Указанные ниже пути относительные; реальные исходники и построенный граф остаются на вашем компьютере.

## 1. Подготовить проект

Ожидаемая структура:

```text
мой-проект/
├── src/
│   ├── cf/                 # основная конфигурация
│   └── cfe/
│       ├── Расширение 1/   # корректная выгрузка расширения
│       └── Расширение 2/
└── .gitignore
```

Graphify-1C обнаруживает `src/cf` и непосредственные корректные дочерние каталоги `src/cfe` автоматически. Если исходники расположены иначе, можно передать путь к конфигурации и повторить `--extension` для каждого нужного расширения.

Установите Python 3.10+, Git и `pipx`. `pipx` создаёт для Graphify-1C отдельное окружение. Оно не меняет уже установленный оригинальный `graphify`:

```powershell
python -m pip install --user pipx
python -m pipx ensurepath
# На Windows разрешите Git длинные пути для сборки парсера BSL:
git config --global core.longpaths true
python -m pipx install --suffix=-1c 'graphifyy[onec] @ git+https://github.com/alexjamk/Graphify-1C.git'
```

Откройте новый терминал, перейдите в **корень своего проекта 1С** и проверьте команду:

```powershell
graphify-1c --help
```

Опция `--suffix=-1c` переименовывает исполняемый файл форка в `graphify-1c` и его окружение в `graphifyy-1c`. Оригинальный `graphify` остаётся отдельной командой. В одном обычном Python-окружении эти пакеты ставить не следует: оба содержат модуль `graphify`. На macOS/Linux замените `python` на `python3`, если именно так называется интерпретатор, и пропустите команду `git config` для Windows.

Парсер BSL 0.1.7 пока собирается из закреплённого исходного коммита, так как этой версии ещё нет в PyPI. Если установка сообщает об отсутствии компилятора C/C++, установите сборочные инструменты для вашей ОС и повторите `pipx install`.

В `.gitignore` проекта 1С добавьте:

```gitignore
graphify-out/
```

Не размещайте выгрузки конфигураций или результаты анализа в публичном репозитории без отдельного решения об их публикации.

## 2. Построить граф один раз

Из корня проекта 1С:

```powershell
graphify-1c analyze ./src --out graphify-out/graph.json --html graphify-out/graph.html
```

Для нестандартного расположения исходников:

```powershell
graphify-1c analyze ./src/cf `
  --extension './src/cfe/Расширение 1' `
  --extension './src/cfe/Расширение 2' `
  --out graphify-out/graph.json --html graphify-out/graph.html
```

Команда печатает число узлов, связей, расширений и диагностику разрешения вызовов. Для графа свыше 5000 узлов рядом с HTML автоматически создаётся `graphify-out/graph.sqlite`. Если SQLite-файла нет, создайте его явно:

```powershell
graphify-1c index build graphify-out/graph.json graphify-out/graph.sqlite
```

Первый полный анализ крупной конфигурации требует времени и памяти. После изменения исходников выполните `graphify-1c update .` из корня проекта. Команда распознаёт 1С, сохраняет пути результатов и явно выбранные расширения предыдущего анализа и перестраивает граф и SQLite. Для проекта без предыдущего анализа она обнаруживает стандартную структуру `src/cf` и `src/cfe/*`. В 1С это пока **полный повторный анализ**, а не быстрая инкрементальная обработка изменённых файлов. Если оригинальный Graphify установлен отдельно, используйте команду форка с суффиксом `-1c`.

## 3. Проверить граф до подключения ассистента

Найдите объект по имени:

```powershell
graphify-1c index search graphify-out/graph.sqlite 'ЗаказКлиента'
```

Скопируйте точный `id` из ответа и откройте его связи:

```powershell
graphify-1c index neighbors graphify-out/graph.sqlite '1c://Document/ЗаказКлиента' --direction in --relation EXTENDS
```

`search` возвращает до 20 совпадений, `neighbors` — до 10 связей по умолчанию. Для следующих страниц используйте `--limit 10 --offset 10`, затем `--offset 20` и так далее до пустого ответа. Это обязательно для вопроса «найди **все** места использования». Сужайте запрос через `--relation` и `--direction`: входящие `calls` — известные вызывающие методы, входящие `EXTENDS` — заимствующие расширения, входящие `query_reads` — методы с чтением таблицы. Для объекта метаданных проверьте также `references` и `type_reference`. Максимальный размер страницы — 30 записей, вывод команды — 12 КиБ. Если ответ превышает предел, уменьшите `--limit`. Не передавайте ассистенту весь `graph.json` и не повышайте предел загрузки JSON: большой граф 1С нужно запрашивать через SQLite. Подробный [рабочий порядок агента](AGENT_WORKFLOW.md) показывает, как переходить между конфигурацией, объектом, модулем и расширением.

Для краткой карточки узла используйте `graphify-1c index explain graphify-out/graph.sqlite '<точный id>'`. Направленный путь между двумя точными ID ищет `graphify-1c index path graphify-out/graph.sqlite '<id начала>' '<id конца>'`; ответ `truncated=true` сообщает, что достигнут предел обхода. Эти команды работают через SQLite и не загружают большой JSON.

Перед обходом многочисленных связей получите короткие счётчики через `graphify-1c index groups graphify-out/graph.sqlite '<точный id>' --direction in`. Если нужен полный перечень, выполните `graphify-1c index export graphify-out/graph.sqlite '<точный id>' graphify-out/usages.jsonl --direction in --relation calls`: все записи попадут в локальный JSONL, а в ответ агенту вернутся только количество и размер файла. Не выводите весь JSONL в диалог; исследуйте нужные строки поиском или страницами `neighbors`.

Для интерактивного просмотра большого графа:

```powershell
graphify-1c serve graphify-out/graph.html
```

Откройте напечатанный локальный адрес. Начальная схема показывает группы типов; поиск находит объект, затем связи выбираются по типу и направлению и загружаются страницами по 20. Сервер слушает только `127.0.0.1`. Для небольшого графа HTML можно открыть напрямую.

## 4. Подключить ассистента

Ассистенту нужен доступ к **каталогу проекта 1С и локальному терминалу**. При работе только в обычном веб-чате ChatGPT локальные файлы и команды недоступны: выполните команды сами и приложите небольшой результат `search`/`neighbors` вместе с нужным фрагментом исходника. Не загружайте полный граф.

| Среда | Где работать | Файл с постоянными инструкциями |
| --- | --- | --- |
| ChatGPT Desktop в режиме Work с доступом к локальной папке и терминалу | Открыть корень проекта 1С | [пример запроса для ChatGPT](examples/CHATGPT_PROMPT.md) |
| Codex CLI или приложение Codex | Открыть корень проекта 1С | [AGENTS.md](examples/AGENTS.md) в корне проекта |
| Claude Code | Запустить Claude Code в корне проекта 1С | [CLAUDE.md](examples/CLAUDE.md) в корне проекта |
| VS Code с GitHub Copilot Chat | Открыть корень проекта 1С в VS Code | [.github/copilot-instructions.md](examples/copilot-instructions.md) |

Скопируйте содержимое соответствующего примера в указанный файл **своего проекта 1С**. Если такой файл уже есть, добавьте раздел про граф, сохранив остальные инструкции. Запускайте новый сеанс ассистента после изменения файла, чтобы он прочитал инструкции.

В Graphify есть команды установки навыка для Codex, Claude и VS Code. Они сохраняют общий сценарий Graphify. Навык этого форка (`graphify/skill-agents.md`) теперь содержит отдельный маршрут 1С, но автоматически создаваемые общие инструкции могут ссылаться на `GRAPH_REPORT.md` и `graphify query`. Для проекта 1С добавьте шаблон из этой инструкции: `graphify-1c analyze` не создаёт `GRAPH_REPORT.md`, а запрос к большому JSON может загрузить весь граф в память. Установка навыка необязательна; команды `graphify-1c index` работают без него.

### ChatGPT

В ChatGPT Desktop выберите Work (если он доступен), откройте локальную папку проекта 1С и вставьте [готовый запрос](examples/CHATGPT_PROMPT.md). Попросите сначала выполнить `search`, затем проверить найденный `id` через `neighbors` и открыть указанные в ответе строки исходников. В веб-чате без локального терминала выполните эти команды сами и передайте только их ответы; ассистент не сможет обновить граф или открыть файлы самостоятельно.

### Codex

Создайте `AGENTS.md` в корне проекта 1С по [шаблону](examples/AGENTS.md). Откройте этот корень как рабочую папку Codex и задайте, например:

> Какие расширения заимствуют документ `ЗаказКлиента`? Покажи связи `EXTENDS` и пути к исходным XML.

Codex должен использовать локальную команду `graphify-1c index`, а вывод графа сверять с исходником перед изменением кода.

### Claude Code

Создайте `CLAUDE.md` по [шаблону](examples/CLAUDE.md), затем запустите Claude Code из корня проекта. Пример запроса:

> Найди методы, которые вызывают `ОбработкаПроведения` выбранного документа, и проверь исходные модули для каждой найденной связи.

Шаблон работает сам по себе. При желании можно дополнительно установить общий навык командой `graphify claude install --project`, но проверьте, чтобы созданные ею правила для `GRAPH_REPORT.md` не подменили правила 1С в `CLAUDE.md`.

### VS Code с GitHub Copilot Chat

Откройте корень проекта 1С в VS Code, создайте `.github/copilot-instructions.md` по [шаблону](examples/copilot-instructions.md) и откройте чат в режиме, которому доступен терминал. Пример запроса:

> Найди связь от проведения заказа к записи регистра. Сначала покажи факты графа, затем проверь BSL в исходниках.

Если агенту запрещён запуск терминала, вручную выполните `search` и `neighbors`, затем вставьте их короткий вывод в чат. Команда общего Graphify `graphify vscode install` может настроить Copilot, но её инструкции ориентированы на универсальный граф; после неё всё равно используйте шаблон 1С.

## 5. Как оценивать ответ

- Требуйте точный `id` узла, тип связи, `source_file` и `start_line` из графа.
- Открывайте исходный XML/BSL для важных выводов. `INFERRED` означает вывод resolver, `AMBIGUOUS` — несколько возможных целей; динамические вызовы и сложный поток данных могут остаться неполными.
- Если граф устарел после правки, выполните `graphify-1c update .` перед ответом об изменённых файлах.
- При очень большом проекте начинайте с поиска и одной группы связей. Обзор браузера и ответы API ограничены по размеру; они не пытаются рисовать весь граф.
