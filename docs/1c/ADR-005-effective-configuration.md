# ADR 005: Effective Configuration как вычисляемое представление

Статус: предложено, 18 сентября 2026 года.

## Контекст

Физический граф хранит отдельные узлы основной конфигурации и каждого расширения. Связи `EXTENDS`, `BEFORE`, `AFTER`, `INSTEAD` и `CHANGE_CONTROL` описывают модификации, но сами по себе не задают подтверждённый порядок применения нескольких расширений.

## Предлагаемая модель

Effective Configuration строится как вычисляемая проекция поверх физического графа, без изменения исходных узлов и связей. Для выбранного базового метода проекция собирает все входящие перехваты и сведения об их расширениях. Если достоверный порядок расширений доступен из метаданных проекта, он хранится отдельным атрибутом и используется при построении цепочки. Если порядка нет, проекция возвращает набор модификаций с отметкой «порядок неизвестен», не выдавая его за последовательность выполнения.

`INSTEAD` и `CHANGE_CONTROL` не следует автоматически превращать в простой линейный вызов базового метода: точная семантика зависит от платформы и приоритета расширений. Перед реализацией исполняемой цепочки требуется проверить правила платформы и реальные метаданные порядка.

## Последствия

Текущий граф остаётся достоверным источником для анализа «какие расширения меняют метод». Будущее API проекции может использовать стабильные `1c://` ID и атрибуты происхождения, не создавая фиктивных физических объектов.
