# Рабочий порядок агента для большой конфигурации 1С

Graphify-1C нужен прежде всего как **индекс связей для агента**. Он связывает метаданные с конфигурацией, расширениями и BSL-кодом. Визуализация помогает исследовать граф, но типичный ответ строится из нескольких небольших запросов к SQLite и проверки найденного XML/BSL.

## Перед вопросом

Работайте из корня проекта с `src/cf` и `src/cfe/*`. Постройте граф:

```powershell
graphify-1c analyze ./src --out graphify-out/graph.json --html graphify-out/graph.html
```

Если SQLite не появился автоматически, создайте его:

```powershell
graphify-1c index build graphify-out/graph.json graphify-out/graph.sqlite
```

После изменений исходников выполните `graphify-1c update .`. Эта команда сохраняет выбранные расширения и пути результатов последнего анализа, затем полностью перестраивает граф 1С. Инкрементальная обработка только изменённых файлов пока не реализована. Храните `graphify-out/` локально и исключите его из Git, если не приняли отдельного решения о публикации данных.

## Модель графа

| Узел или связь | Что означает | Как использовать |
| --- | --- | --- |
| `Configuration`, `Extension` | Корни основной конфигурации и расширений | Начало навигации по метаданным. |
| `Document`, `Catalog`, `InformationRegister`, `CommonModule` и другие виды | Объекты метаданных | Ищите по имени и типу; проверяйте принадлежность. |
| Реквизит, табличная часть, форма, модуль, процедура, функция | Состав и код объекта | Переходите от объекта к реализации и обратно. |
| `contains` | Родитель → дочерний элемент | Входящие связи дают владельца, исходящие — состав. |
| `EXTENDS` | Объект расширения → заимствованный объект базы | Найдите все расширения, изменяющие объект. Собственный объект расширения может не иметь этой связи. |
| `BEFORE`, `AFTER`, `INSTEAD`, `CHANGE_CONTROL` | Метод расширения → целевой метод базы | Учитывайте все расширения отдельно; порядок совместного выполнения граф не вычисляет. |
| `calls`, `calls_server`, `handler` | Связи методов и обработчиков | Входящие связи показывают известных вызывающих. |
| `references`, `type_reference`, `uses_command` | Использование метаданных, типов и команд | Ищите места использования вне прямых вызовов. |
| `query_reads`, `writes` | Чтение таблиц запросом, запись регистра | Проследите влияние изменения структуры данных. |

У каждого узла есть `source_type` (`configuration` или `extension`), `extension_name`, `source_file` и при наличии `start_line`. У ребра есть `relation` и `confidence`. `EXTRACTED` означает прямое извлечение, `INFERRED` — разрешение анализатором, `AMBIGUOUS` — несколько возможных целей. Проверяйте исходники для существенных выводов.

## Ответить на вопрос без чтения всей конфигурации

1. **Найти кандидатов.** `graphify-1c index search graphify-out/graph.sqlite 'ЗаказКлиента'`. Поиск по подстроке может вернуть разные виды узлов, в том числе одинаковые имена из разных расширений. Выберите точный ID по типу, происхождению и файлу. Для следующей страницы поиска добавьте `--limit 20 --offset 20`.
2. **Выбрать направление и отношение.** `--direction in` показывает кто ссылается на цель, `out` — что использует сама цель. Запрашивайте сначала один `--relation`, чтобы не засорять контекст.
3. **Пройти все страницы при запросе «все места».** Например:

   ```powershell
   graphify-1c index neighbors graphify-out/graph.sqlite '<точный ID>' --direction in --relation calls --limit 100 --offset 0
   graphify-1c index neighbors graphify-out/graph.sqlite '<точный ID>' --direction in --relation calls --limit 100 --offset 100
   ```

   Продолжайте с шагом 100 до пустого ответа. Повторите для других отношений, которые соответствуют вопросу. Первые 100 связей нельзя выдавать за все связи.
4. **Расширить только нужную ветвь.** Для найденного метода спросите входящую `contains`, чтобы увидеть модуль; для модуля повторите запрос и найдите объект метаданных. Для объекта просмотрите входящую `EXTENDS`, а для метода — четыре вида перехватов.
   `graphify-1c index explain graphify-out/graph.sqlite '<точный ID>'` выдаёт карточку узла, количество связей по типам и ограниченный образец. `graphify-1c index path graphify-out/graph.sqlite '<ID начала>' '<ID конца>'` ищет направленный путь по дисковому индексу с ограничением глубины и числа посещённых узлов; `truncated=true` означает, что предел обхода достигнут.
5. **Проверить исходники.** Откройте указанные XML/BSL-файлы и строки. Если строка не сохранена, откройте небольшой участок по имени узла. Сопоставьте результат графа с исходником перед правкой или утверждением о поведении.
6. **Дать компактный ответ.** Укажите ID, тип связи, источник, расширение и файл. Отделите установленные факты от предположений и непокрытых динамических вызовов.

## Примеры вопросов

**«Какие расширения меняют документ?»** Найдите базовый `Document`, запросите входящие `EXTENDS`, затем для базовых методов — входящие `BEFORE`, `AFTER`, `INSTEAD`, `CHANGE_CONTROL`. Соберите результаты по `extension_name`. Объекты расширения и методы могут находиться в разных файлах.

**«Где используется реквизит?»** Найдите реквизит, проверьте входящие `references` и `type_reference`. Затем посмотрите владельца через входящую `contains`. Текстовые обращения к реквизиту без разрешённой связи всё ещё могут потребовать адресного поиска по исходникам.

**«Что затронет изменение регистра?»** Найдите регистр, проверьте входящие `writes`, `query_reads`, `references` и `type_reference`. Для методов найдите владельцев через `contains`, затем проверьте BSL-запросы и движения.

**«Кто вызывает метод?»** Найдите метод по полному ID, соберите все входящие `calls` и подходящие `calls_server` по страницам. Проверьте варианты с одинаковым именем из основной конфигурации и расширений, а также неоднозначность разрешения.

## Что не следует заключать из графа

- Пустой список означает «анализатор не нашёл связь данного типа». Динамические вызовы, сложная сборка запросов и межпроцедурный поток данных покрыты не полностью.
- Связь перехвата указывает целевой метод, но не гарантирует порядок нескольких расширений и итоговое поведение эффективной конфигурации.
- Универсальные `graphify-1c explain`, `path` и `query` могут читать полный JSON в память. На большом 1С-графе используйте `index search/neighbors/explain/path`. Дисковый `index path` ограничивает обход и не обещает ответ, если предел достигнут.
- Не выводите в контекст весь `graph.json` и не читайте целый модуль, если достаточно нескольких найденных строк. Это уменьшает объём инструментальных ответов, но не гарантирует фиксированный процент экономии токенов.
